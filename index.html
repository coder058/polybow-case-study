Development notes / March–May 2026

Building Polybow.

Could a bot act on a price mismatch before the order book caught up?

Polymarket’s short-duration crypto markets compare an opening and closing oracle price. I built a Python system to capture that reference, follow prices and place orders when the book appeared to disagree.

Python / WebSockets / Chainlink RTDS / Binance / CLOB API / AWS Lightsail

01 / Development

Polybow → StratA → StratB → UC

  1. 01

    Polybow

    The first version bought likely winners near expiry. Expensive entries left little upside even when the direction was right. The early oracle feed updated roughly every 27 seconds; faster Binance data and, later, Chainlink RTDS and live order books became part of the pipeline.

  2. 02

    StratA

    I moved to mid-priced contracts: $0.40–$0.72, with 11–15 seconds remaining. The aim was more upside per winning trade, not simply a higher win rate. Cheaper entries could also reverse before resolution.

  3. 03

    StratB

    A fork of StratA tested wider entry windows and larger BTC-to-opening-price gaps. WebSocket-triggered “hot eval” let a book update run the decision immediately. On the Dublin AWS Lightsail VPS, cached metadata and a warmed execution path reduced work between the signal and the order.

  4. 04

    UC Ultra-cheap

    The next branch explored $0.01–$0.20 contracts and maker orders below the ask; a later patch also tried a taker leg. Cheap winning shares drove the wallet’s run-up, but fast submission did not guarantee a fill. Later cheap-entry results failed to repeat it.

I used AI assistance for implementation, strategy experiments and log analysis. Actual fills and wallet reconciliation were the checks on those outputs. These were overlapping branches, not four isolated A/B tests.

02 / Execution

What became faster

Hot eval bypassed the polling wait. Its per-market re-evaluation gate changed from 50 to 5 ms. The Dublin setup used HTTP/2 and faster signing; subsequent changes preloaded token metadata and fetched missing metadata in parallel.

03 / Live outcome

The run-up and what changed

$19.98 → $210.22Initial trading collateral → observed liquid peak

−$13.70Lifetime settled trading cash P&L

The run-up came mainly from a small cluster of low-priced BTC winners. Speed was part of the implementation, but incomplete trade-to-bot records prevent attributing those gains to the Dublin/hot-eval combination alone.

The May 2 code patches removed paper-state entry guards and bypassed the simulator. Later runs traded more, and the next 17 sub-$0.10 markets all lost. That documents the change and the deterioration—not proof that a single code or exchange patch killed the edge. The wallet subsequently fell to dust.
